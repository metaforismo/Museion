## Design decisions

| Before | After | Why |
| --- | --- | --- |
| Composer counter, status dot and repeated subtitle | Expanding input, send button and original Maia beside the composer | Keep attention on the learner’s explanation |
| 2,000-character question cap and thirty-turn cutoff | Current question delivered intact; no lifetime conversation cutoff | Preserve the full reasoning; retain burst and usage controls |
| Artificial character-by-character reply | Whole validated explanation arrives together | Make replies easier to read and inspect |
| Generic opening plus misconception explanation | Specific safe diagnosis replaces the generic question | Each sentence should help choose the next move |
| Small gold token over controls | Original Maia character marks the actual relevant control | Connect tutor guidance to the activity |
| Empty controls after lesson resume | Restore only the learner’s actual last attempt | Keep the checked activity consistent with its result |
| Full-width course hero and narrow trail | Overview beside a shared winding learning path | Make the next lesson and progress legible |
| Separate generated player | Generated lessons use the same LessonPlayer, Maia and engine | Keep source courses and Originals consistent |
| Stale generated-course completion and misconception cues | Persist observed progress; clear superseded cues | Refresh should show the actual current learning state |
| Blank account loading pill | Usable Sign in baseline and bounded session lookup | Session failure cannot leave navigation empty |
| Fading and shrinking subject icons | Named subjects remain readable in all scroll phases | Rapid scroll must not hide the information |
| Unstructured footer links | Explore and Trust & access groups | Improve navigation and touch spacing |
